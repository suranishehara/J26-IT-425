    Annotation guide
    recommend: request options; explain: reason for a previous choice; compare: contrast alternatives; update_preferences: change a constraint; knowledge_question: general fact/definition; greeting: social opening; clarify: unresolved reference or insufficient information. Annotate the user's goal, not a keyword. For multi-intent or context-dependent cases, defer with notes rather than force a label.
    Entities: JSON array of {"mention":"silk","value":"silk","negated":false}. Canonical labels follow the existing fashion-term ontology. Slots: JSON object for occasion, weather, setting, style, colours or budget_lkr. Removals: JSON array of slot names. Empty []/{} means you checked and found none; blank means unannotated. Repeated mentions need normalized start offsets. Unsupported ontology terms belong in notes, not invented labels.
